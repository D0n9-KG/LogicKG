# Extraction Design: Schema-Guided DAG with Chained Recursion

**Status**: Design v1 (2026-08-13). Pre-implementation.
**Supersedes**: The simple truncation approach (max_chars=8000) in extractor.py.

## 1. Problem

Current extraction feeds 8000 chars (first 4000 + last 4000) to a single LLM call. Papers are 40-60k chars → 80% of content is lost. This caused:
- 9/50 zero-atom papers (18%)
- "0 real gaps" conclusion may be unreliable (gaps in truncated middle not seen)
- QA answers anchored to truncated text (missing middle data)

RAGA solves this with per-paragraph ReAct + KG, but we must not copy RAGA (novelty risk + complexity). We need a different incremental approach.

## 2. Design: Schema-Guided DAG with Chained Recursion

### 2.1 Core Idea

Three-phase extraction using a directed acyclic graph (DAG) guided by schema fields, executed via chained recursive LLM calls (fresh context per node, blackboard for cross-node state).

**Key distinction from RAGA**:
- RAGA: bottom-up, per-paragraph ReAct, KG as cross-segment carrier
- Ours: top-down, schema-guided DAG, blackboard + compact summary as carrier
- RAGA: every paragraph read (50+ calls/paper)
- Ours: only DAG-keyed sections read (5-8 calls/paper)

### 2.2 Phase 0: Structure Mapping (1 LLM call, full text)

Input: full paper text (40-60k chars, fits in DeepSeek 64k context)
Output: structure map (compact, ~500 tokens)

The LLM reads the entire paper in one call but only outputs a compact structure map, not atoms. This avoids "lost in the middle" for extraction (the full read is for structure identification, not fine-grained extraction).

```
Structure map format:
{
  "sections": [
    {"name": "Abstract", "char_range": [0, 1200], "discourse_role": "summary"},
    {"name": "Introduction", "char_range": [1200, 8000], "discourse_role": "context"},
    {"name": "Method", "char_range": [8000, 25000], "discourse_role": "definition"},
    {"name": "Results", "char_range": [25000, 45000], "discourse_role": "observation"},
    {"name": "Discussion", "char_range": [45000, 55000], "discourse_role": "interpretation"},
    {"name": "Conclusion", "char_range": [55000, 60000], "discourse_role": "claim"}
  ],
  "key_entities": ["μ(I)", "shear rate", "inertial number", "glass beads"],
  "schema_field_map": {
    "MATERIAL": ["Introduction", "Method"],
    "BOUNDARY_CONDITION": ["Method"],
    "CLOSURE": ["Method", "Results"],
    "CONTRIBUTION": ["Results", "Discussion", "Conclusion"],
    "CONTRIBUTION_RELATION": ["Discussion"]
  },
  "dag": {
    "nodes": [
      {"id": "n1", "section": "Method", "fields": ["MATERIAL", "BOUNDARY_CONDITION", "CLOSURE"], "deps": []},
      {"id": "n2", "section": "Results", "fields": ["MEASUREMENT", "NUMERIC", "experimental_finding"], "deps": ["n1"]},
      {"id": "n3", "section": "Discussion", "fields": ["CONTRIBUTION", "CONTRIBUTION_RELATION"], "deps": ["n1", "n2"]},
      {"id": "n4", "section": "Conclusion", "fields": ["RESEARCH_QUESTION", "CONTRIBUTION"], "deps": ["n3"]}
    ]
  }
}
```

**Discourse roles** (per Scientific Discourse Tagging, arXiv 1909.04758):
- summary (Abstract)
- context (Introduction)
- definition (Method — entities/parameters defined here)
- observation (Results — measurements/data reported here)
- interpretation (Discussion — mechanisms/claims argued here)
- claim (Conclusion — final assertions)

**Schema-guided DAG construction**: The LLM maps schema fields to sections based on where they typically appear. This creates a DAG where each node is (section, schema_fields) and edges are dependencies (Results depend on Method's definitions, Discussion depends on Results' observations).

### 2.3 Phase 1: Chained Extraction (N LLM calls, one per DAG node)

Each DAG node is executed via a Chained RLM call (arXiv 2608.05124):
- **Fresh context** (no accumulated conversation history)
- Receives: section text + compact summary from predecessor nodes + blackboard (atoms extracted so far)
- Outputs: atoms with Evidence span + Confidence score

```
Node execution:
  input = section_text[char_range] + blackboard_summary + schema_fields_for_this_node
  output = [atoms with evidence_span and confidence]

  For each atom:
    - evidence_span: exact text from the section that supports this atom
    - confidence: 0.0-1.0 (LLM self-assessed)
    - discourse_role: from Phase 0 structure map

  After extraction:
    - Update blackboard with new atoms
    - Generate compact summary of what was extracted (for next node)
    - If confidence < 0.5 for any atom → flag for lookup phase
```

**Blackboard**: A JSON structure holding all atoms extracted so far + a compact text summary. This replaces RAGA's KG as the cross-section carrier. Lighter than Neo4j, no query language needed.

**Compact summary**: Generated by the LLM at each node, ~200 tokens. Contains: "Extracted: μ(I)=0.279+I_0/(I+I_0) from Method; glass beads d=0.53mm; shear rate range 10-100 s⁻¹ from Results; mechanism: inertial number controls friction from Discussion." This carries cross-section context to the next node without full history.

**Adaptive fission** (per TopoAgent, arXiv 2607.14658): If a node produces atoms with avg confidence < 0.4, split that node into sub-nodes (e.g., Method → Method-Setup + Method-Constitutive-Law). This replaces RAGA's multi-round ReAct within a paragraph — instead of looping, we split the task.

### 2.4 Phase 2: Grounding + Lookup (1-2 LLM calls)

**Grounding** (deterministic, no LLM):
- For each atom with evidence_span, check if evidence_span appears verbatim in the paper text
- If exact match found → grounded (keep)
- If no match → hallucination (discard)
- This is LMDX's approach (arXiv 2309.10952): exact-text-match validation, not LLM judge

**Lookup** (1 LLM call, only for flagged low-confidence atoms):
- Re-read the specific section where the atom was extracted
- Try to find the evidence span
- If found → upgrade confidence
- If not found → discard

**Rebind detection** (our unique contribution):
- For atoms where the same value appears in multiple sections (e.g., μ_s=0.38 in Method and Results):
  - Check discourse_role: if "definition" in Method and "observation" in Results → same value, different role (not rebind)
  - If "definition" in Method but "claim" in Conclusion with different entity → potential rebind
- This is the discourse-role-based binding check that RAGA doesn't have

### 2.5 Cost Model

| Phase | Calls | When |
|---|---|---|
| Phase 0 (structure map) | 1 | Always |
| Phase 1 (chained extraction) | 4-8 | Depends on DAG size (sections × schema fields) |
| Phase 2 (grounding) | 0 (deterministic) | Always (no LLM) |
| Phase 2 (lookup) | 0-1 | Only if low-confidence atoms flagged |
| Phase 2 (rebind check) | 0 (deterministic) | Always (no LLM) |
| **Total** | **5-10** | Per paper |

**Adaptive budget** (per HAB, arXiv 2606.1965):
- Simple papers (short, single contribution): 5 calls
- Standard papers (medium, 2-3 contributions): 7 calls
- Complex papers (long, multiple mechanisms): 10 calls
- Budget determined by Phase 0 structure map complexity

### 2.6 Integration with Agent System

This replaces the current Extract capability in `extractor.py`. The agent's other capabilities (Fuse, GapDiscovery, Validate, ExtendSchema, QAGenerate) remain unchanged but operate on the output of this new extraction:

```
Agent flow (updated):
  1. AdaptiveExtract (NEW): Phase 0 + Phase 1 + Phase 2 → atoms with evidence + confidence
  2. Fuse (unchanged): MARY fusion if multi-LLM
  3. GapDiscovery (unchanged): detect schema-fitting failures
  4. Validate (unchanged): evidence-linked validation
  5. ExtendSchema (unchanged): append + provenance
  6. QAGenerate (unchanged): QA pairs from grounded atoms
```

Hooks integration:
- `on_extraction_complete` fires after Phase 2 (grounding verified)
- `on_gap_found` fires from Phase 1 if LLM uses entity_type not in schema
- `on_schema_extended` fires from ExtendSchema

### 2.7 Implementation Plan

1. `structure_mapper.py`: Phase 0 — full-text structure mapping
2. `chained_extractor.py`: Phase 1 — DAG-ordered chained extraction with blackboard
3. `grounding.py`: Phase 2 — exact-text-match + lookup + rebind detection
4. Update `agent.py`: Replace `extractor.extract()` with new `AdaptiveExtract`
5. Update `extractor.py`: Keep old `extract_single_llm` as fallback for short papers

## 3. Differentiation from RAGA (Confirmed)

| Dimension | RAGA | Ours |
|---|---|---|
| Reading strategy | Bottom-up per-paragraph ReAct (50+ calls) | Top-down schema-guided DAG (5-10 calls) |
| Cross-section context | KG (Neo4j) search_kg | Blackboard + compact summary (Chained RLM) |
| Section awareness | None (flat paragraph queue) | Discourse roles + section structure |
| Hallucination check | browse_context (LLM self-audit, 34.8% miss rate) | exact-text-match (deterministic, 0% miss for exact matches) |
| Rebind detection | None | Discourse-role-based binding check |
| Task splitting | Multi-round ReAct within paragraph | Adaptive fission (split node into sub-nodes) |
| Budget | Unbounded (reads every paragraph) | Adaptive (5-10 calls, HAB-style budget) |
| Schema guidance | None (schema-agnostic extraction) | Schema fields → section mapping (DAG construction) |

**Claimable novelty**: "Schema-guided DAG extraction with discourse-role-aware grounding" — the combination of (1) schema-field-to-section mapping for DAG construction, (2) discourse-role-based rebind detection, (3) deterministic exact-text-match grounding, and (4) Chained-RLM-style fresh-context extraction is not found in RAGA, TopoAgent, Chained RLM, LMDX, or any surveyed work.

## 4. Limitations (honest)

1. Phase 0 still requires full-text in one LLM call (64k context) — papers exceeding this need a fallback (truncation or two-pass structure mapping)
2. Discourse role assignment depends on LLM's understanding of paper structure — may misclassify
3. DAG construction is LLM-generated, not deterministic — different runs may produce different DAGs
4. Blackboard is a flat text structure, not a queryable KG — cross-section entity resolution is less precise than RAGA's search_kg
5. Adaptive fission may cascade (split → sub-split → ...) if confidence stays low
6. Grounding via exact-text-match is strict — paraphrased evidence will be discarded (false negative)
